# Task 37, Item 2 — The HOS Instrument, Fully Specified

Script: `task37_2_held_out_specificity.py`

## The statistic

**Held-Out Specificity (HOS):** does β's held-out correlation with |error|
exceed what a direction fit by the *same procedure* to a meaningless target
achieves on the *same* held-out data?

    HOS(v) = | Spearman( X_holdout · v ,  |error|_holdout ) |

Spearman because only ordering is claimed; absolute value because a difficulty
direction is meaningful up to sign.

## The three-way split

The pool is split **FIT / CAL / HOLDOUT**, with HOLDOUT (25% of pool) carved out
and used for **nothing except scoring** — never to fit β, never to calibrate,
never to select anything. Disjointness from FIT is asserted at runtime.

## The null — the part that matters most

For j = 1…200: permute the FIT-split error labels, fit
`v_j = RidgeCV(features → π_j(|error|_fit))` with the **identical estimator,
alphas, features and normalization** as β, and score `HOS(v_j)` on the **same**
holdout slice.

Permutation preserves the target's marginal distribution and the entire fitting
procedure, destroying only the feature↔error relationship. Per the Item 2
guardrail, the null is **fitted directions, not untrained random vectors** — an
untrained null would reintroduce exactly the fitted-vs-random confound Item 1
was built to detect.

    percentile = fraction of j with HOS(v_j) < HOS(β);   PASS iff ≥ 0.95

## Why this avoids both prior failure modes

| failure mode | why HOS is immune |
|---|---|
| **DS degeneracy** (Task 36): δᵢ constant because the ridge path is affine | HOS **never computes a model-output derivative**. It uses the projection `X·v` directly, which varies across points on any model. |
| **fitted-vs-random geometric bias** (the Item 1 hypothesis) | The null is generated by the **same fitting procedure**, so "was this direction fitted" is held constant between candidate and null. |

## Stated limits

- HOS is **correlational by design**. It tests whether β's ordering of points
  tracks realized error better than a permutation-fitted direction — not whether
  perturbing along β causes prediction change. It is a *specificity* test, not a
  causal-adjacency test. That is the appropriate question for a linear model,
  where the causal-adjacency framing is what degenerated.
- It uses held-out **outcomes**, so like Check 2 and DS it is a validation
  diagnostic only and can never enter interval construction.
- The permutation null tests against "no feature↔error relationship." It does
  not test against a *weaker but real* alternative direction, so a pass means
  "better than chance," not "the best possible direction."
